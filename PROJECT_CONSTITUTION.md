# Constituição do Projeto

Este documento define as regras fundamentais do projeto. Deve ser consultado antes de qualquer alteração relevante.

## Princípios fundamentais

- Simplicidade antes de complexidade.
- Código legível, claro e fácil de manter.
- Segurança considerada desde o início.
- Documentação obrigatória para decisões, requisitos e alterações relevantes.
- Português de Portugal (PT-PT) como idioma principal do website.
- English e Français como idiomas adicionais.
- Python confirmado como linguagem de backend.
- PHP não será utilizado.
- Django é uma possibilidade a avaliar na fase de arquitetura técnica, não uma decisão final nesta fase.
- PostgreSQL é uma possibilidade preliminar, mas a decisão final da base de dados está pendente.
- Dependências novas apenas com justificação documentada.
- Arquitetura apenas deve ser alterada com documentação e autorização.
- Não criar conteúdo fictício como se fosse real.
- Não depender de uma IA específica.

## Fonte de verdade

A fonte de verdade do projeto é o repositório GitHub e a documentação nele existente.

Ferramentas como ChatGPT, OpenAI Codex, Claude Code, Gemini, GitHub Copilot ou outras podem apoiar o trabalho, mas não substituem a documentação do projeto.

## Identidade do projeto

O projeto representa Miguel Cardoso e deve funcionar como portfólio profissional + hub pessoal.

O site deve apresentar quem é o Miguel, aquilo que faz, aquilo que gosta e aquilo que cria, sem ser concebido exclusivamente como CV online ou exclusivamente como ferramenta de procura de emprego.

## Alterações futuras

Qualquer alteração relevante deve respeitar:

- o estado atual do projeto;
- os requisitos aprovados;
- as decisões registadas no decision log;
- as decisões de arquitetura documentadas;
- as regras de segurança;
- o histórico registado no changelog.
