# Decision Log

Este documento regista decisões relevantes do projeto. Decisões pendentes devem permanecer marcadas como pendentes ou futuras.

## Decisões aprovadas

### DEC-001 — Fonte de verdade

Estado:
Aprovada.

Decisão:
O GitHub e a documentação do repositório são a fonte central de verdade do projeto.

Consequência:
Nenhuma IA ou histórico de chat deve ser necessário para compreender o projeto.

### DEC-002 — Identidade pública

Estado:
Aprovada.

Decisão:
O nome apresentado será Miguel Cardoso.

Consequência:
A documentação e futura interface devem usar esta identidade pública.

### DEC-003 — Posicionamento

Estado:
Aprovada.

Decisão:
O posicionamento base é: “Sou estudante de Engenharia Informática, interessado em desenvolvimento, tecnologia e criação de conteúdo.”

Consequência:
A comunicação deve ser pessoal, profissional e acessível.

### DEC-004 — Conceito do site

Estado:
Aprovada.

Decisão:
O site será um portfólio profissional + hub pessoal, não apenas um CV online.

Consequência:
A estrutura deve permitir conteúdos profissionais, criativos e pessoais.

### DEC-005 — Público-alvo

Estado:
Aprovada.

Decisão:
O público principal inicial será seguidores e público geral, especialmente visitantes provenientes do Instagram. O público secundário inclui recrutadores, empresas, profissionais de tecnologia, programadores, potenciais clientes, colaboradores e parceiros.

Consequência:
O site deve ser compreensível para não técnicos e permitir profundidade progressiva para visitantes profissionais.

### DEC-006 — Áreas conceptuais iniciais

Estado:
Aprovada.

Decisão:
As áreas iniciais são Tecnologia, Fotografia e Fitness, com maior peso para Tecnologia e Fotografia.

Consequência:
A arquitetura deve permitir novas áreas no futuro e não deve fixar estas três como únicas.

### DEC-007 — Direção visual

Estado:
Aprovada.

Decisão:
A direção visual será minimalista pessoal/criativa.

Consequência:
O design deve ser clean, profissional, pessoal, criativo e confortável para os olhos.

### DEC-008 — Referência conceptual

Estado:
Aprovada.

Decisão:
`https://diogotc.com/` pode ser usado apenas como referência conceptual de minimalismo.

Consequência:
Não copiar design, layout, código, identidade visual ou conteúdo.

### DEC-009 — Home conceptual

Estado:
Aprovada.

Decisão:
A Home terá Hero, Explora, Sobre mim, Projetos em destaque, Fotografia/criação, Contacto e Footer.

Consequência:
A arquitetura da informação deve respeitar esta estrutura conceptual.

### DEC-010 — Idiomas

Estado:
Aprovada.

Decisão:
O site suportará PT-PT como idioma principal, EN e FR como idiomas adicionais.

Consequência:
A arquitetura deve permitir tradução organizada sem duplicar a aplicação.

### DEC-011 — Tecnologia confirmada e excluída

Estado:
Aprovada.

Decisão:
Python está confirmado como linguagem de backend. PHP não será utilizado.

Consequência:
A stack final Python será definida na fase de arquitetura técnica.

### DEC-012 — Imagem pessoal e logótipo

Estado:
Aprovada.

Decisão:
Não será usada fotografia pessoal nem logótipo inicialmente.

Consequência:
A estrutura deve permitir adicioná-los futuramente sem alteração profunda.

### DEC-013 — Instagram

Estado:
Aprovada.

Decisão:
Instagram será uma origem principal de tráfego, mas o site não deve depender da API ou disponibilidade do Instagram.

Consequência:
Integração inicial deve ser simples ou limitada a ligações, salvo decisão futura.
